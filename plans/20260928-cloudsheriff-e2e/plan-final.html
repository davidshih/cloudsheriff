1. Goal and non-goals

Goal

One command, uv run python -m cloudsheriff scan, performs the full demo contract against the lab in terraform/:

  1. Assume CloudSheriffAuditRole (read-only, ExternalId) and get short-lived STS credentials.
  2. Create an ephemeral Daytona sandbox from a prebuilt snapshot that contains Prowler, run a targeted Prowler scan with those credentials, download the JSON-OCSF file, and delete the sandbox (always, in finally).
  3. Normalize the OCSF findings using only stable structured fields.
  4. Take a canonical snapshot of every security group that appears in the findings, and attach it as structured evidence.
  5. Diff against the previous state in SurrealDB using three axes: Evaluation, Lifecycle, and Change.
  6. Apply a deterministic alert gate. The LLM never decides whether an alert exists.
  7. For each security-group alert, attribute the change with CloudTrail Event History (who, when, which API).
  8. Ask Claude for an explanation of each already-decided alert, and trace the whole run plus the LLM call in Arize.
  9. Persist the scan, state, and events to SurrealDB and print a readable report.

Also: uv run python -m cloudsheriff build-image builds the Daytona snapshot once.

Non-goals (explicitly out of scope)

  • Agentic investigation or remediation proposals. This is reserved as the declared new feature for the event day.
  • Web UI, dashboard, ElevenLabs, Anchor Browser, multi-account or multi-region, Prowler mutelist, BENCHMARK_CHANGE, Daytona domain allow-lists, CI workflows.
  • Any change to terraform/ or scripts/ code.

3. Approach

Add one small Python package with six modules. Keep all decision logic pure and tested, and keep each integration thin.

cloudsheriff/
  __init__.py      empty
  __main__.py      argparse CLI (build-image, scan) + pipeline orchestration + report printing
  engine.py        PURE: normalize OCSF, finding key, SG evidence, diff (3 axes), alert gate
  aws.py           boto3, read-only: assume audit role, SG canonical snapshots, CloudTrail attribution
  scanroom.py      Daytona: build snapshot, run Prowler in an ephemeral sandbox, always delete it
  store.py         SurrealDB: load state, last scan, save scan/state/events
  explain.py       Arize tracing setup + Claude explanation with deterministic fallback
tests/
  fixtures/prowler_demo.ocsf.json
  test_engine.py  test_store.py  test_aws.py  test_explain.py  test_main.py

Division of work between the sandbox and the orchestrator

Only Prowler runs inside Daytona. It is the heavy third-party scanner, so it is the part worth isolating. The SG snapshot and CloudTrail lookup are small, deterministic, and our own code, so they run on the orchestrator with the same read-only STS session. That keeps them unit-testable with stub clients. The orchestrator's base identity is the admin profile, and it is used only for sts:AssumeRole.

Alternatives rejected

  • Run the snapshot and CloudTrail steps inside the sandbox too. That needs script upload and output parsing, and it cannot be tested offline. The security story does not change, because it is the same read-only credential.
  • Local Prowler without Daytona. This defeats the ephemeral scan room, which is the Daytona prize story.
  • A SurrealDB server for tests. The SDK's embedded mem:// gives real SurrealDB semantics with no server and no network, so the implementer can run the tests.
  • An LLM-decided severity or alert. This is rejected by design, because the gate is the safeguard.
  • A CLI entry point via the build backend. package = false is simpler; run with python -m cloudsheriff.
  • Pydantic models. Frozen dataclasses are enough.

Functions:

  • finding_key(account, region, check_id, resource_uid) -> str: returns sha256("|".join([...]).encode()).hexdigest()[:24].
  • normalize(ocsf: list[dict]) -> list[Finding]: for each item, read metadata.event_code, status_code, severity.lower(), finding_info.title, resources[0]'s uid/name/type/region and labels (default [], stored as a tuple), cloud.account.uid, and unmapped.compliance filtered to keys that start with "CIS" (default {}). Skip items with no resources. Do not read message, status_detail, or resources[].data.
  • sg_id_from_uid(resource_uid) -> str | None: returns the part after ":security-group/" if present, else None.
  • canonical_sg_rules(rules: list[dict]) -> list[dict]: the input is the SecurityGroupRules list from EC2 describe_security_group_rules. Keep only IsEgress == False. Map each rule to {"proto": IpProtocol, "from": FromPort, "to": ToPort, "src": CidrIpv4 or CidrIpv6 or "sg:"+ReferencedGroupInfo.GroupId or "pl:"+PrefixListId}. Drop rule IDs and descriptions, because descriptions are free text and would cause false drift. Deduplicate, then sort by (proto, from, to, src), using -2 as the sort value for None ports.
  • evidence_hash(evidence: dict) -> str: returns the sha256 of json.dumps(evidence, sort_keys=True, separators=(",",":")).
  • attach_evidence(findings, sg_rules_by_id: dict[str, list[dict]]) -> list[Finding]: for findings whose sg_id_from_uid is present in the map, return a copy (dataclasses.replace) with evidence = {"ingress": canonical_sg_rules(rules)} and evidence_hash set. Leave all other findings unchanged.
  • diff(prev: dict[str, dict], findings: list[Finding], scanned_checks: set[str], now: str) -> tuple[list[Transition], dict[str, dict]]. prev maps each key to a stored state dict (fields in Step 5). The function returns the transitions, plus the state records to upsert, keyed by key. Rules:

    1none, or goneFAILFAILACTIVENEWwrite
    2none, or gonePASSPASSACTIVENEWwrite
    3PASSFAILFAILACTIVEREGRESSIONwrite
    4PASS, same hashPASSPASSACTIVEUNCHANGEDwrite (refresh last_evaluated)
    5PASS, different hashPASSPASSACTIVECHANGEDwrite
    6FAIL, same hashFAILFAILACTIVEUNCHANGEDwrite
    7FAIL, different hashFAILFAILACTIVECHANGEDwrite
    8FAILPASSPASSRESOLVEDCHANGEDwrite
    9anything: none, gone, PASS, or FAILMANUALNOT_EVALUATEDACTIVEUNCHANGEDnone. MANUAL is never persisted and never takes part in lifecycle or change. A MANUAL key still counts as present for rows 10 and 11, so it never produces RESOURCE_GONE. before_status is the previous last_status if there is one (else None); after_status is "MANUAL"; the descriptive fields come from the finding.
    10exists, not gone; its check_id is NOT in scanned_checks; key absent(not scanned)NOT_EVALUATEDACTIVEUNCHANGEDnone (carry forward; a targeted rescan never resolves unscanned controls)
    11exists, not gone; its check_id IS in scanned_checks; key absent(resource disappeared)NOT_EVALUATEDRESOURCE_GONECHANGEDwrite the previous record with gone=True, last_evaluated=now
    12gone; key absentanyno transition, no update
    "Same hash" compares evidence_hash values, and None equals None. A hash difference matters only when both hashes are non-None; None versus a value counts as the same, so a missing snapshot never creates drift. before_status is the previous last_status (None when there is no previous state or it is gone). after_status is the finding status (None for rows 10 and 11). before_evidence and after_evidence carry the previous and current evidence. For rows 10 and 11, fill the descriptive fields (check_id, title, labels as a tuple, compliance, and so on) from the previous record. A written state record contains: key, check_id, title, severity, resource_uid, resource_name, region, account, labels (list[str]), compliance (dict), last_status, evidence, evidence_hash, first_seen (keep the previous value, or now), last_evaluated (now), and gone (False, or True for row 11). Return transitions sorted by (change != "REGRESSION", change, key) so that regressions print first.
  • alert_gate(transitions, baseline: bool) -> list[Transition]: returns [] if baseline. Otherwise returns the transitions where evaluation == "FAIL" and change in ALERT_CHANGES and severity in ALERT_SEVERITIES. It must never read labels or any text field. Add a comment that this is the safeguard.
  • rule_str(rule) -> str: returns "tcp/22 <- 0.0.0.0/0". When proto is "-1", render "all". When from equals to, show a single port; for a range, show a-b; when a port is None or -1, show no port part ("icmp <- ...").
  • rules_delta(before_evidence, after_evidence) -> tuple[list[dict], list[dict]]: returns (added, removed) from the two "ingress" lists, treating None as an empty list.

Step 5: cloudsheriff/store.py (SurrealDB)

NS, DB = "cloudsheriff", "lab"
  • class Store, a context manager. __init__(url, user=None, password=None). __enter__ does self.db = Surreal(url).__enter__(); if url starts with ws or http, also signin({"username": user, "password": password}). Then use(NS, DB). __exit__ closes the connection.
  • load_state() -> dict[str, dict]: {r["key"]: r for r in db.select("finding")}, with the id field removed from each dict.
  • last_scan() -> dict | None: db.query("SELECT * FROM scan ORDER BY finished_at DESC LIMIT 1"); returns the first row or None, with id removed.
  • save_scan(scan: dict, transitions: list[Transition], updates: dict[str, dict], alerts: list[dict]) -> None: all writes happen in one SurrealQL transaction, built as a single db.query(sql, vars) call: 
    BEGIN TRANSACTION;
UPSERT $f0 CONTENT $d0;  UPSERT $f1 CONTENT $d1; ...      -- one per state update, $fN = RecordID("finding", key)
CREATE $scan_id CONTENT $scan;                             -- RecordID("scan", scan["scan_id"])
CREATE $e0 CONTENT $v0; ...                                 -- events, $eN = RecordID("event", f"{scan_id}_{key}")
COMMIT TRANSACTION;
    Pass the record IDs as RecordID variables; do not build IDs with type:: functions. Events are written for each transition whose change is not UNCHANGED, or which is an alert. Each event is {**asdict(t), "labels": list(t.labels), "scan_id", "alert": bool, "attribution", "explanation", "explanation_source"}, with alerts (a list of {"key", "attribution", "explanation", "explanation_source"}) merged in by key.
    Verified planner behavior (SDK 2.0.0): a failed transaction is fully rolled back on both mem:// and ws://. However, embedded raises an exception while ws returns without raising, and the query's return value is not informative (it is None on ws even on success). So after the query, save_scan must run db.select(RecordID("scan", scan_id)). If that returns an empty list, raise RuntimeError("scan not persisted; transaction rolled back"). The state is therefore never partially updated, so a regression can never be silently lost to UNCHANGED on the next run. All timestamps are ISO-8601 UTC strings. scan_id is utcnow().strftime("%Y%m%dT%H%M%SZ").

Step 6: cloudsheriff/explain.py (Arize + Claude)

  • MODEL = os.environ.get("CS_MODEL", "claude-opus-5-5").
  • SYSTEM_PROMPT, verbatim intent: "You are the explanation layer of CloudSheriff, a read-only CIS drift monitor. A deterministic policy has already decided that this alert exists. You cannot create, downgrade, suppress, or re-prioritize alerts. Write at most 120 words for an on-call engineer: what changed (before/after rules), why it matters for the named CIS control, who changed it and when (if attribution is present; if it is null, say attribution is pending because CloudTrail delivery lags), and one suggested manual remediation AWS CLI command.   • build_user_message(t: Transition, attribution: dict | None) -> str (pure, tested): json.dumps(facts, indent=2), where facts = check_id, title, severity, change, resource_uid, resource_name, region, compliance, before_rules, after_rules, added, removed (rules rendered with engine.rule_str) and attribution. Then append "\n<untrusted_resource_metadata>\n" + "\n".join(t.labels) + "\n</untrusted_resource_metadata>".
  • fallback_text(t, attribution) -> str (pure, tested): a deterministic one-paragraph summary with the change, resource, title, added rules, actor (or "attribution pending"), and a revoke command template for each added world-open rule: aws ec2 revoke-security-group-ingress --group-id <sg> --protocol <p> --port <port> --cidr <cidr>.
  • explain(t, attribution, client=None) -> tuple[str, str]: returns (text, source), where source is MODEL or "fallback". Use client or anthropic.Anthropic() and call client.beta.messages.create(model=MODEL, max_tokens=16000, betas=["server-side-fallback-2026-07-01"], fallbacks="default", output_config={"effort": "low"}, system=SYSTEM_PROMPT, messages=[{"role":"user","content": build_user_message(...)}]). If stop_reason == "refusal", or there are no text blocks, return (fallback_text(...), "fallback"). Wrap both the client construction and the call in try/except Exception, not only anthropic.APIError. The installed SDK raises TypeError when no credentials resolve, and this is best-effort enrichment for an alert that is already decided. On any exception, print a one-line warning containing the exception class name only, never the key, and return the fallback. Otherwise join the text of the blocks with type == "text".

8. Risks and rollback

  • Daytona Tier 1/2 egress. Regional AWS endpoints are allow-listed; iam.amazonaws.com may not be. The demo profile needs only EC2, VPC, and STS (regional). If the cis profile hits blocked IAM calls, that is a known limitation to document, not a blocker for the demo.
  • Prowler in debian_slim. The pip install might need extra system packages. This is found at build-image time in stage 5, and the fix is a run_commands apt line in build_image.
  • CloudTrail lag. Handled: None means "attribution pending", and the runbook says to wait about 5 minutes.
  • LLM refusal or outage. Handled: deterministic fallback text, and the alert is unaffected.
  • SDK drift. Versions are pinned in uv.lock.
  • Rollback. All code is new files plus doc edits: git checkout -- README.md HACKSPRINT_BOUNDARY.md .gitignore pyproject.toml and rm -rf cloudsheriff tests. There is no data migration.
